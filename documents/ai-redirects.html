Where the AI went one way and you went another

A log of the redirects during the build, in order. Each one says what the assistant did or proposed, what you wanted instead, and what changed as a result. Kept because the pattern is more useful than any single entry.

Before the build

Diagram timing planning

AI Draw the architecture diagram at step 6, after the code, so it matches what was built.
You Asked whether it should be first instead. There was an argument for both.

Result: both. A ten-minute sketch first, as the plan in picture form, then corrected at the end to match the code. The spec was written that way.

Commit attribution first push

AI Would have added a "Co-Authored-By: Claude" line to every commit, per its default.
You Short messages, no AI co-author line.

Result: every commit is a plain one-line message. Saved as a standing preference.

During the build

Checking commits against the brief after the README push

AI Was committing feature by feature against the spec it had written.
You Every commit should be checked against the two requirement documents, not just the spec.

Result: a requirements pass before each push from then on, and eventually the checklist page.

Pushing during a deployment the database incident

AI Pushed a health-check commit about a minute after you attached the database. That push cancelled the deployment that would have granted the database user its permissions. Every deploy after that failed at startup.
You "Don't do anything, just talk to me." Then, later, caught a second push during a deploy and asked whether it was the same mistake.

Result: no pushes without your say-so while deployments were in flight. The cause and fix went into the README. The second push was harmless, and the AI explained why, but it should have waited anyway.

What the overview document should be three attempts

AI First version: a catalogue of every function with its signature and file. Second version: diagrams with signatures as labels, still dense.
You "Diagrams and visuals with short high-level explanations." Then: "It doesn't really explain anything. Simple, no jargon, not like explaining to a PhD."

Result: the third version opens with a coat-check analogy, tells two stories end to end, and uses one line of code per step as a label. That is the one in the repo. The AI's instinct was to be complete; yours was to be understood.

Stop building or keep building with about fifty minutes left

AI "Stop adding features. Read the code, rehearse, sign out."
You Wrote a note proposing a frontend, extremely minimal, in DigitalOcean's style.

Result: the AI reconsidered: a static page is additive and cannot break the API, unlike the metrics and rate-limit ideas it had argued against. Built with a timebox. It became the demo centrepiece.

Strict input on the page first UI feedback

AI Used the browser's built-in URL field, which rejects youtube.com without a scheme.
You "When I put in youtube.com it says please put in a URL. Is that a problem?"

Result: the page adds https:// when it is missing. The API stays strict; the page is the forgiving layer.

Labels on the result card UI feedback

AI Showed "custom name" or "generated name" next to the Copy button.
You Confusing. Remove both.

Result: removed. The card shows the short link, the destination, and Copy.

Past links on the page UI feature

AI Had left "past links" for a future list endpoint behind auth.
You Wanted to see and delete past links in the UI now.

Result: a per-browser history with live click counts and a Delete button, using only the existing API. The auth-backed version stays in next steps.

Tasteful interaction UI feedback

AI Shipped the page with a single hover colour and nothing else.
You Hover states, press feedback, visual responses.

Result: hover lift and shadow, press-down, focus rings, a green flash on Copy, a fade-in on the result card, row highlight in the history list.

Talking points format documents

AI Wrote the sheet as Markdown.
You Wanted HTML to open in a browser.

Result: converted and the Markdown removed. Every document since has been HTML.

Gating deploys on tests pipeline

AI Had left tests and deploys running in parallel, and written it up as an honest gap rather than fixing it.
You "Seems like a win." Created the token, added the secret, turned off deploy-on-push.

Result: the deploy job now runs only after both test jobs pass. Verified twice end to end. The gap in the Q&A page was rewritten as closed.

Unit tests testing

AI Had written 47 integration tests and one unit test, and called the brief's "unit or integration" satisfied.
You "Should I write more unit tests? It is one of the givens."

Result: a unit test file for the pure functions: code generation, alias rules, timestamp formatting, the log formatter. 61 tests. The README now says which kind does what.

Comments in the code the last pass

AI Wrote comments and docstrings as it went, in its own register: "collapse Pydantic's error list", "structured JSON logging", "the factory that picks a backend", "liveness".
You Delete the unnecessary ones. Make the necessary ones simpler and easier to digest. Cut jargon where it can be cut, keep it where cutting it would confuse.

Result: every comment and docstring in the app, the tests, the workflow, the app spec, the Dockerfile and the page was reread. One was deleted (it repeated the test's name). The rest were rewritten in plain words: "Is this container alive, and which database is it using", "Add columns that older database files are missing", "Last on purpose: /{code} would otherwise capture /healthz too". Words like Pydantic, UTC, stdout and 410 stayed, because they name the actual thing and a softer word would be wrong.

The other direction

The pasted token early

You Pasted a GitHub token into the chat so the AI could push.
AI Declined to use it, said to treat it as exposed and revoke it, and set up an SSH key instead so no secret ever had to pass through the conversation.

Result: the same rule held for the DigitalOcean token later: it went straight from the console into GitHub's secret store.

The pattern, in one paragraph. The AI defaulted to completeness, caution, and its own vocabulary. You redirected toward being understood, toward the customer's experience, and toward closing gaps rather than documenting them. Nearly every redirect made the result simpler or more honest. The one time the AI held its ground, it was about a secret.
  • When it wrote for itself, you asked it to write for a reader.
  • When it protected the schedule, you weighed the demo.
  • When it named a gap, you asked whether it could just be fixed.
  • When it acted during a fragile moment, you asked it to stop and talk.
